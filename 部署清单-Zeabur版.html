三、导入项目并部署

4
新建项目
点击 + New Project（新建项目），给项目起个名字，比如 moshi-daming。
5
添加服务 — 从 GitHub 导入
在项目页面点击 + Add Service → 选择 Git Repository
从列表中选择你的 GitHub 仓库，确认分支（main），点击 Add Service。
6
自动识别与构建
Zeabur 会自动检测到 package.json，识别为 Node.js 项目。
它会自动执行：npm install → npm start（即 node server.js）。

不需要额外配置，Zeabur 的智能检测已经够用了。
但如果自动识别有问题，你可以在服务设置中手动指定： 
# zbpack.json（可选，仅在自动识别失败时添加）
{
  "build_command": "npm install",
  "start_command": "npm start"
}
7
等待构建完成
在 Deployments 标签页可以实时看到构建日志。大约 30 秒到 1 分钟后会显示 Deployed。
如果构建报错 "Cannot find module 'express'"，说明 npm install 没跑。检查 package.json 的 start script 是不是 "start": "node server.js"。

附：常见问题

Q：部署后显示 502 错误？

检查环境变量 LLM_API_KEY 是否正确配置，并且已经重新部署（Redeploy）。

Q：页面能打开但发消息没反应？

打开浏览器开发者工具 → Network 标签 → 查看 /api/chat 请求的状态码和响应。常见原因：API Key 无效、DeepSeek 余额不足。

Q：Zeabur 的 Dockerfile 会不会干扰？

Zeabur 检测到 Dockerfile 后会用 Docker 模式部署。两种方式都行，效果一样。如果你想让 Zeabur 用原生 Node.js 模式（更快启动），可以在环境变量里加 ZBPACK_IGNORE_DOCKERFILE=true，或者把 Dockerfile 从项目中移除。

Q：如何更换模型？

在 Zeabur 环境变量中添加 LLM_MODEL=你的模型名，然后 Redeploy。支持任何 OpenAI 兼容的 API。
